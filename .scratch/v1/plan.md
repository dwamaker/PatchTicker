# vuln-radar v1 계획 (grill-with-docs 2026-11-07 반영)

용어는 `CONTEXT.md`, 굳힌 결정은 `docs/adr/` 참고.

## 목표

공익 목적 공개 페이지. 로그인 없음. 보안 사건을 신속하게 공유하고, 방문자가 자기 제품만 걸러 볼 수 있게 함.
계기: sshole(CVE-2026-123158). HN 1면(11-05) → CVE Crowd → Sploitus 순으로 퍼졌고, 사건 판단을 사람이 일일이 해야 했음.

## 화면 (Board)

- 위: **주목 사건** 최대 10개, 최근 7일에서 점수순 (실제 악용 중 CISA KEV, HN 등 화제성, 심각도 9.0 이상, 큐레이터 언급)
- 아래: 전체 사건 최신순
- 필터: 제품 선택(제품 이름만, 버전 없음) + 검색창. 검색은 제목·요약·제품·CVE ID·버전 글자에 실시간 반응
- 필터는 브라우저(localStorage) + URL 쿼리에 저장, 서버로 안 감
- 언어: 브라우저 언어 자동 + 전환 버튼, 주소 하나
- 사건마다: 요약, 대처법(있으면), **대표 언급** 링크 크게(공식 공지 → 발견자 설명 → CVE → 토론 순), 나머지 언급 작게, PoC 저장소도 링크, "잘못됐어요" → GitHub 이슈 양식
- "참고용, 자세한 내용은 원문 확인" 고지

## 데이터

- 단위: **사건**. CVE 0개 이상과 언급 여러 개가 붙음. CVE 미배정 사건도 바로 올리고, CVE가 붙으면 합침 (ADR 0001)
- 제품 목록: CVE의 CPE + AI가 본문에서 뽑은 제품명, 최근 90일에 나온 것만
- 저장: R2 월별 JSON이 주 저장소, 각 수집기의 SQLite는 백업. 페이지는 최근 3개월(90일)만 읽음. 기간 확장 = 파일 더 읽기 (ADR 0002)

## AI 요약 (2단계: 속보 → 요약)

- **속보 (즉시, AI 없음)**: 사건이 들어오면 원문 데이터만으로 바로 보드에 올림. 원문 한 줄 설명(영어), 심각도, 제품, KEV 여부, 대표 언급 링크. 한국어는 "요약 준비 중" 표시
- **요약 (Batch API, 50% 할인)**: 매 수집 주기(15분)에 새 사건을 Batch로 보내고, 다음 주기에 결과를 받아 붙임. 대부분 1시간 안에 끝남(최대 24시간)
- **예외 = 즉시 요약 (일반 API)**: 주목 사건 후보(새로 KEV 등재, HN 등 화제, 심각도 9.0 이상, 언급만 있는 CVE 미배정 사건)는 속도가 중요하므로 바로 요약
- 캐싱: 지시문을 예시 포함 512토큰 이상으로 만들고 `cache_control` 적용. Batch는 1시간 TTL 권장(쓰기 2배, 읽기 0.1배). Batch와 캐싱 할인은 겹쳐 적용됨
- `claude-haiku-5-5`, 한 요청에 한국어·영어 함께. 내용: 짧은 요약 + 대처법(있으면) + 대표 언급 안내. 숫자·경계값은 원문 그대로
- effort `low`, 출력은 짧게(출력 단가가 입력의 5배). Haiku 5.5는 생각 토큰이 max_tokens에 포함되므로 max_tokens 여유 있게
- 가격(MTok, 10만 토큰 이하 요청): 입력 $0.10, 출력 $0.50, Batch $0.05/$0.25, 캐시 쓰기 5분 $0.125·1시간 $0.20, 캐시 읽기 $0.01. flex 같은 저가 등급은 없음(11-07 공식 문서 확인)
- 다시 요약하는 경우: 공식 공지·패치 버전이 새로 나옴, KEV 등재, CVE가 새로 붙음. 사건당 최대 3번
- 예산: Console 워크스페이스에 월 사용 한도를 걸어 둠(11-07, 사용자). 실제 예상 사용은 월 ~$11. 한도에 닿으면 요약만 멈추고 목록은 계속 갱신
- 물량 추정: 새 CVE 하루 평균 574건(cvelistV5 30일, 최대 ~800) + 뉴스 → ~650건/일

## 0단계: 확인 결과 (2026-11-07)

- **오라클 Always Free**: 7일 동안 CPU p95 < 20%, 네트워크 < 20%, 메모리 < 20%(A1만)가 **모두** 맞으면 회수될 수 있음. 종량제(PAYG) 계정 예외는 문서에 없음. 아웃바운드 월 10TB. 회수돼도 .104 예비가 이어받음
- **Cloudflare Pages(무료)**: 빌드 월 500회, 사이트당 파일 2만 개, 파일당 25MiB. 대역폭 한도는 문서에 없음
- **R2(무료)**: 저장 10GB-월, 쓰기(Class A) 월 100만, 읽기(Class B) 월 1천만, 전송 무료, 객체 최대 5TiB. **r2.dev 주소는 개발용**(속도 제한, 운영 비권장) → 공개 전에 Cloudflare 계정의 도메인을 버킷에 연결해야 함. 페이지와 데이터 도메인이 다르면 버킷 CORS 설정 필요
- **NVD API**: 키 없이 30초에 5회, 키 있으면 30초에 50회, 요청 사이 몇 초 쉬기 권장. 고지 문구 필수: "This product uses data from the NVD API but is not endorsed or certified by the NVD." → 수정 시각 범위 조회로 한 번에 받고, 무료 키 발급
- **CVE 목록**: 재배포 허용. 사본에 MITRE 저작권 표시와 라이선스 문구를 넣어야 함 → 페이지 하단에 표기. cvelistV5는 약 7분마다 갱신, deltaLog.json은 30일치
- **CISA KEV**: CC0, JSON 피드 `known_exploited_vulnerabilities.json`. CISA 로고 사용 금지
- **HN Algolia**: IP당 시간 1만 회
- **GitHub API**: 비인증 시간 60회·검색 분당 10회, 토큰 쓰면 시간 5천·검색 분당 30회 → 권한 없는 토큰 하나 사용
- **oss-security**: `seclists.org/rss/oss-sec.rss` 있음, robots.txt가 RSS 경로는 막지 않음
- **토큰 실측(11-07, Haiku 5.5, effort low, 실제 CVE 5건)**: 입력 504~972, 출력 504~859 토큰, 건당 평균 **$0.00041** → 하루 650건이면 **월 약 $8, Batch면 약 $4**. 한국어 품질 양호, 대표 링크로 OpenSSH 릴리스 노트를 골랐음. 고칠 점: "256자 초과"를 "256자 이상"으로 옮김 → 지시문에 "숫자·경계값은 원문 그대로" 추가. CVE 레코드만으로는 임시 대처법(PasswordAuthentication no)이 안 나옴 → 언급 본문도 같이 넣어야 함
- **영어 전용 비교(11-07, 같은 CVE 5건)**: 건당 **$0.00028**(월 ~$5.4, Batch ~$2.7). 한·영 동시는 $0.00039~0.00041로 **약 40% 더 듦**, 입력은 거의 같고 출력만 늘어남. 한·영 동시 유지(예상 월 ~$4, Batch 기준). "256자" 경계 문제는 CVE 공식 설명 자체가 "between 256 and 1024"라서 생긴 것(모델 오류 아님) → 발견자 글 등 언급 본문을 같이 넣어야 바로잡힘
- **프롬프트 캐싱**: 요청에 `cache_control`을 넣는 방식(Console 스위치 아님). Haiku 5.5는 512토큰 이상인 앞부분만 캐시됨. 시험용 지시문(~300토큰)은 못 미침 → 실제 지시문에 예시를 넣어 512토큰을 넘기고 캐싱 적용. 절감은 월 $1 미만 수준

- **즉시 요약 실측(11-07, 티켓 06, 실제 지시문·JSON 스키마·언급 본문 포함, 요청 6회)**: sshole(발견자 글 + 릴리스 노트 + CVE 레코드) + 최신 CVE 2건(CVE-2026-99271, CVE-2026-99272, 리눅스 커널) × effort low/medium. 6건 모두 코드 검사 통과. 지시문 캐시 2,244토큰: 첫 요청에서 쓰고 이후 5건은 읽음(effort를 바꿔도 캐시 유지)
  - low: 입력 1,613~3,456 + 캐시 2,244, 출력 1,532~1,628, 건당 $0.00097~0.00139(평균 **$0.00116**)
  - medium: 출력 1,585~2,158, 건당 $0.00098~0.00137(평균 $0.00123). 6건 합계 **$0.0072**
  - **결정: effort low 유지.** 품질은 비슷함(둘 다 257~1024자 경계, 10.6p2, `PasswordAuthentication no`를 정확히 옮김, 대표 언급은 발견자 글). low 쪽 sshole 대처법이 오히려 더 구체적(`apk upgrade openssh`, 설정 파일 경로). medium은 출력이 최대 33% 늘고 얻는 것이 없음
  - 11-07 측정($0.0004)의 약 3배: 언급 본문을 넣어 입력이 늘고(설계상 필요), 출력이 1.5천 토큰으로 늘어남(한·영 조건·대처법 필드 + 생각 토큰). 즉시 요약은 주목 후보만이라 하루 수십 건 × $0.0012 = 월 ~$1. **티켓 07 주의**: 전체 650건/일에 같은 요청이면 Batch로도 월 ~$11 → 지시문으로 출력을 줄이거나 Batch 입력에서 페이지 본문을 빼는 것을 검토

- **쉬운 설명 실측(11-08, 티켓 10, effort low, 요청 4회 합계 $0.0034)**: 같은 요약 요청에 언어별 `easy`(30단어 이내)와 언어 무관 `fixed`·`command`·`stopgap`·`devices`를 추가. 대신 summary를 "2~3문장"에서 "최대 2문장"으로, "모든 필드 짧게, 서로 반복 금지"를 넣음. 지시문 캐시 2,244 → 2,777토큰(+533, 캐시 읽기라 건당 $0.000005)
  - sshole: 입력 5,127 + 캐시 쓰기 2,777, 출력 **1,522**, $0.00162(캐시 쓰기 포함). 06의 low 1,532~1,628과 같은 수준. `command` = `apk upgrade openssh`, `stopgap` = `PasswordAuthentication no`, `fixed` = 10.6p2, 257~1024 경계 유지
  - CVE-2026-99271(커널, 06에서도 측정): 입력 2,739 + 캐시 읽기, 출력 **1,289**, $0.00095. 06 low(1,532 이상)보다 **약 16% 적음**
  - CVE-2026-19868(SonicWall SonicOS, KEV, CVE 레코드만): 첫 응답은 코드 검사에서 거절(숫자 "2", MFA를 "2단계 인증"으로 쓴 것으로 보임, 06부터 알려진 숫자 검사 한계), 재시도 통과. 출력 669 / 585, $0.00043 / $0.00038. `devices`는 빈 목록(레코드에 기기 모델명 없이 Gen7/Gen8만 있음)

## 검증

- sshole 재현: 11-05 HN 글, sshhole.com, oz9un/sshole, CVE-2026-123158이 한 사건으로 묶이는지. 제품 "OpenSSH" 필터에 보이고 "Dropbear"만 고르면 안 보이는지. 요약에 "musl + PAM 없음 + 비밀번호 로그인"과 대처법(10.6p2, PasswordAuthentication no)이 나오는지. 대표 언급이 OpenSSH 릴리스 노트인지
- 예비 전환: 오라클 수집기를 멈추면 45분 뒤 .104가 이어받고, 다시 켜면 물러나는지
- 소스별 한 번씩 실제 호출해 형식 확인 (대량 호출 금지)
- 공개 후 curl로 페이지·JSON 갱신 확인
