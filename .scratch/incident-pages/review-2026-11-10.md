## Fix

Owner decisions
1. **Owner: a moved slug whose survivor has no page yet answers 302 to the Board (`/#i=<survivor id>`)**, not 410.
   Once the survivor gets a page the same address answers 301 as now. 410 stays only for a move or survivor past
   90 days. Update tests (`tests/page.test.mjs` encodes the old 410) and ticket 04's Comments.
2. **Owner: source links on Incident pages open in a new tab like the Board's** (DESIGN.md "Do": `target=_blank`,
   `rel="noopener noreferrer"`, the hidden "새 탭에서 열림" / English twin as the Board uses). Our own links (Board,
   other language, Report a mistake) follow whatever the Board does for the same kind of link.
3. **Owner: old documents are cleared by an R2 lifecycle rule** on the `pages/` prefix (delete 100 days after the last
   write), set by the owner's session at deploy, not by code. In code: document it in `docs/development.md`, and keep
   the single index documents from growing without end: drop entries older than 90 days from `moves.json` and any
   slug no longer in the page set from `page_hashes.json` (check what it does today).

Spec axis
4. `cached()` stores only `res.ok`: also cache 301/302/404/410 with a short `cache-control` (404 shorter), so
   crawlers on expired pages do not read R2 every time. Keep 503 uncached.
5. Fail closed on render errors too: a malformed document (no `mentions`, `cves` not a list) must answer the 503 note,
   never a runtime 500 (spec: "never a half-rendered page"). Applies to page, feed and sitemap renderers.
6. The feed's plain explanation and what-to-do must match the page (story 34: "a page and its Board row never
   disagree"): use the same `easyLine` and `easyAction` the page uses, so an item with only a command still has a
   what-to-do.
7. A hard cap of 50,000 URLs per sitemap file (spec: under one sitemap file's limit): truncate the oldest with a
   `shortcut:` comment if ever reached.
8. `write_moves` writes "moved to" documents only for absorbed IDs that had a page (their slug is in the page index).
9. Ticket 01: tick the acceptance boxes that are met (status says done).

Standards axis
10. `shortcut:` comment in `write_moves` lacks its "when to upgrade" half (repo convention
    `shortcut: <limit>, <when to upgrade>`).
11. DESIGN.md "keep every interactive target at least 44 px": the page's `.links` nav anchors and Mention links.
12. `edge/sitemap.mjs` re-declares `PAGE_DAYS` (and its comment is wrong): import it from `web/board.mjs`; one 90-day
    freshness helper and one `DAY_MS` shared by `shareLink`, `pageResponse` and `sitemapXml`.
13. One shared edge module for what every function uses (`SITE`, escaping, `cached`, the R2 read with 503
    fail-closed, `SLUG`), instead of `edge/feed.mjs` and `edge/page.mjs` serving as each other's library.
14. Name the slug `slug` everywhere (`page.mjs` calls it `name`).
15. Positional pairs in stored documents (`[hash, changed]`, `[survivor, moved]`, `[first_seen, changed]`): since
    nothing is deployed yet, make them small objects with named fields (and update docs/tests), or say in Comments why
    not.
16. CONTEXT.md vocabulary: the 503 note "The feed is unavailable" -> "The RSS feed …". Keep the page's Mention labels
    the same as the Board's UI text (that is deliberate).
17. `docs/development.md` Tests section: describe the new node tests (page, feed, sitemap) and Python tests.
